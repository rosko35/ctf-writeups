plus my study notes. It starts empty on purpose: every writeup is added only after I have solved

## How the repository is organised

```text
tryhackme/    writeups for TryHackMe rooms
hackthebox/   writeups for HackTheBox machines and challenges
picoctf/      writeups for picoCTF / picoGym challenges
other/        everything else (other platforms, own labs)
templates/    writeup template (EN/TR) and a clearly fictional example
tools/        new_writeup.py, build_index.py, check_flags.py
tests/        pytest tests for the tools
notes/        cheat sheets: methodology, commands, Linux privesc, web basics (EN/TR)
```

Each writeup lives in `<platform>/YYYY-MM-DD-room-name/README.md` with screenshots in an `img/` folder next to it.

The file `templates/example-fictional-writeup.md` shows the expected level of detail. It is
**fictional**: an invented machine on a documentation IP range, not a real room, and nothing in it was solved.

## Using the tools

Python 3.11+, standard library only (pytest and ruff are for development).

```bash
python tools/new_writeup.py --platform tryhackme --name "Room Name" --lang en --difficulty easy --category web
python tools/build_index.py          # regenerate the index above (and the Turkish one)
python tools/check_flags.py          # fail if an unredacted flag is present

python -m venv .venv && source .venv/Scripts/activate   # Git Bash on Windows; use .venv/bin/activate on Linux/macOS
pip install -r requirements-dev.txt
pytest && ruff check .
```

CI (GitHub Actions) runs ruff, pytest, `check_flags.py` and `build_index.py --check` on every push.

## Rules I follow

- Only legal targets: intentionally vulnerable machines and challenges on platforms that give me
  permission to attack them, or my own lab. Nothing else, ever.
- No live flags. Flags are redacted (`THM{...}`), and `check_flags.py` enforces it.
- Platform rules about publishing writeups come first:
  - **HackTheBox** forbids publishing writeups for active machines and challenges. I only publish retired content.
  - **TryHackMe** and **picoCTF** have their own rules and they change. I check the current terms
    for each room or competition before publishing, and when a room asks not to be written up, I don't.
- I credit any writeup, article or tool that helped me.

## Why I keep this

I am a university student starting out in security. Writing a challenge up in my own words forces
me to understand why each step worked, gives me something to look back on, and makes it easier
to see what to study next. This is a learning log, not a scoreboard.
